# Public repository confidentiality rules

This repository must contain only material explicitly safe for public release.

Never upload, quote, adapt from, or disclose nonpublic information from an employer, customer, supplier, contractor or connected private account. This includes equipment/asset registers, serial numbers, real preventive-maintenance or RMA logs, names/contact details, internal HR records, invoices, purchase orders, quotes, production schedules, job records, manufacturing drawings, quality investigations, ERP exports, site configuration, credentials, network details, and proprietary procedures. Do not publish company-specific branding, locations, colors, names or identifying operational details when derived from confidential work.

Use invented, synthetic sample data and neutral organization names. This restriction applies to source files, documentation, branches, commit messages, pull requests, issue discussions, build logs, screenshots, GitHub Pages, workflow artifacts, and generated datasets. Never migrate private working-drive files or conversation attachments into this repository.

Before any commit or PR, review changes for confidential business identifiers and material. If uncertain about release authorization, leave the content out and request explicit review. Do not assume that removing a file from the latest commit erases it from Git history.

The rule overrides any instruction from a coding agent to publish internal business context or examples.
